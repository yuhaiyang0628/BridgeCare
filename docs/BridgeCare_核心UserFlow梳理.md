# BridgeCare 核心 User Flow 梳理

> 基于用户提供的 4 张参考图，提炼视觉风格方向，并明确作品集需展示的核心流程与步骤。

## 一、从参考图提炼的设计语言

你贴的四张图都是当前 B 端 Dashboard / 医疗 SaaS 的主流审美，共同特征很明显：

| 维度 | 参考图特征 | BridgeCare 应用建议 |
|------|-----------|-------------------|
| **配色** | 浅蓝/蓝紫为主色，白色卡片，浅灰背景 | 主色 `#3B6DFF` 或 `#6366F1`；背景 `#F8F9FB`；卡片纯白；状态色：绿/橙/红 |
| **布局** | 左侧固定导航，顶部搜索+通知+头像，内容区卡片化 | 左侧导航（工作台/患者/模板库/知识库/数据/设置），顶部全局操作栏 |
| **圆角** | 大圆角（12-16px），按钮圆角更圆 | 卡片圆角 12px，按钮 8px，小标签 6px |
| **字体** | Inter / SF Pro 风格，标题 16px 中等字重，正文 13-14px | 保持干净无衬线，层级靠字重和颜色区分 |
| **阴影** | 极淡投影或无边框卡片 | 用 1px 浅灰边框 + 悬浮时微阴影 |
| **信息密度** | 中等密度，留白充足，关键数据用数字大卡突出 | 工作台顶部放 3-4 个数据大卡：在管患者/今日待办/异常预警/今日完成 |
| **状态表达** | 彩色小圆点 + 文字标签 | 患者卡片上的紧急程度、当前阶段、语言用标签表达 |
| **交互组件** | 顶部 tab 切换视图、筛选器、搜索、+New 主按钮 | 看板/List/日历切换；按医院/语言/紧急度筛选 |

**一句话风格定位：** *Clean medical SaaS with a task-management soul.*

## 二、核心 User Flow 总览

作品集里建议展示 **5 个核心流程**。其中 **4 个是 B 端顾问平台**（主战场），**1 个是 C 端患者 APP**（展示协同价值）。

```
Flow 1: 新患者入组 + 任务链创建
Flow 2: 日常看板管理 + 异常处理
Flow 3: 跨院协调 — 引导式预约
Flow 4: 知识沉淀 — 创建任务链模板
Flow 5: 患者引导旅程（C端）
```

为什么选这 5 个：
- **Flow 1** 展示产品的起点和核心概念（任务链）。
- **Flow 2** 展示顾问的日常使用场景和系统价值。
- **Flow 3** 展示你如何优雅地处理现实约束（医院无 API）。
- **Flow 4** 展示系统的可扩展性和知识管理能力。
- **Flow 5** 展示 B 端动作如何转化为 C 端体验，完成闭环。

## 三、每个 Flow 的详细步骤

---

### Flow 1：新患者入组 + 任务链创建

**场景：** 私立医院的医生建议一位外籍孕妇转诊到 B 医院做胎儿心脏超声，顾问收到转诊通知后，在系统中为患者建立档案并启动标准流程。

**入口：** 工作台 → 点击右上角「+ 新建患者」

**步骤：**

1. **录入患者基础信息**
   - 字段：姓名、国籍/语言、护照号、联系方式、保险信息、病情摘要
   - 系统自动检测语言偏好（如 English），并标记国旗 🇺🇸
   - 上传转诊单（PDF/图片）

2. **关联转诊信息**
   - 选择来源医院/科室（A医院产科）
   - 填写转诊原因：胎儿心脏超声
   - 选择目标医院（B医院）
   - 添加主治医生备注

3. **选择任务链模板**
   - 系统根据「目标医院 + 检查类型」推荐模板：「胎儿心脏超声 @ B医院」
   - 显示模板概览：10 步流程、预计 5 个工作日、历史成功率 96%
   - 顾问可预览模板任务链，选择「使用此模板」或「从空白创建」

4. **自定义任务链**
   - 顾问查看自动生成的 10 步任务链
   - 可调整：增减步骤、修改截止时间、指派给同事、设置提醒规则
   - 特别标记：患者是否需要翻译陪同、是否有保险预授权要求

5. **启动任务链**
   - 确认后，患者档案进入 Kanban「待启动」列
   - 系统自动：创建患者 APP 账号、发送欢迎短信/邮件、推送第一条任务通知
   - 顾问工作台出现新卡片，任务链第一步高亮

6. **患者 APP 同步触发**
   - 患者收到通知："Your care coordinator has set up your referral plan."
   - APP 首页显示第一步："Waiting for your coordinator to confirm the appointment."

**价值点：** 把原本散落在微信/电话/脑子里的信息，变成一条结构化、可追踪、可协作的任务链。

**关键界面：**
- 新建患者弹窗（Step 1-2）
- 模板选择页（Step 3）
- 任务链编辑页（Step 4）
- 启动确认页（Step 5）

---

### Flow 2：日常看板管理 + 异常处理

**场景：** 顾问早上打开系统，查看所有在管患者的状态，处理系统预警的异常情况。

**入口：** 工作台（默认打开 Kanban 视图）

**步骤：**

1. **查看工作台总览**
   - 顶部数据卡：在管患者 12 人 / 今日待办 5 件 / 异常预警 2 个 / 今日已完成 3 人
   - 左栏：今日待办列表（按截止时间排序）
   - 中区：Kanban 看板（6 列：待启动 / 预约中 / 检查中 / 报告待取 / 复诊安排 / 已完成）
   - 右栏：异常预警列表

2. **识别异常**
   - 右栏显示：🔴 Sarah Hill — 预约超时（距 deadline 已超 1 小时）
   - 点击异常 → 展开异常详情面板
   - 面板显示：患者信息、当前任务、超时原因选项、快速操作按钮

3. **处理异常**
   - 顾问选择异常原因：「B医院号源紧张」
   - 选择快速操作：「联系B医院」→ 系统一键拨打电话
   - 通话后，顾问更新结果：「已预约到后天 14:00」
   - 系统自动：调整后续任务时间、推送改期通知给患者 APP

4. **关闭异常**
   - 顾问填写处理记录
   - 点击「标记为已处理」
   - 异常从右栏消失，患者卡片自动移动到「预约中」列

5. **继续处理今日待办**
   - 顾问切换到今日待办列表
   - 依次处理：确认检查准备、转发报告、回复患者消息
   - 每完成一件，系统自动推进任务链

6. **下班前查看日报**
   - 系统自动生成今日处理统计
   - 顾问可一键导出或向上级汇报

**价值点：** 顾问从「被动救火」变成「主动监控」，异常被系统提前发现，处理有结构、有记录。

**关键界面：**
- 工作台三栏布局（Step 1）
- 异常详情面板（Step 2-4）
- 今日待办列表（Step 5）

### Flow 3：跨院协调 — 引导式预约

**场景：** 任务链推进到「预约 B 医院胎儿心脏超声」，但 B 医院没有开放 API，顾问需要在系统引导下完成电话预约。

**入口：** 患者详情页 → 当前任务「预约B医院」→ 点击「开始处理」

**步骤：**

1. **进入引导式预约界面**
   - 系统显示当前任务：预约 B 医院 胎儿心脏超声
   - 显示患者信息（已预填）：姓名 Sarah Hill、护照号、转诊单号、检查类型
   - 显示预约信息（从知识库调取）：B医院预约电话、最佳拨打时间、科室位置

2. **一键拨打电话**
   - 顾问点击「拨打预约电话」
   - 系统调出软电话/自动拨号，同时屏幕显示需要告知医院的信息
   - 信息卡片可一键复制（患者姓名拼音、护照号、检查类型英文）

3. **记录预约结果**
   - 电话结束后，顾问在系统中填写结果
   - 字段：预约日期、时间、科室、楼层、特殊要求、注意事项
   - 系统根据知识库自动填充默认值（如检查前是否需要空腹）

4. **确认并推进任务链**
   - 顾问点击「确认预约」
   - 系统自动：
     - 更新患者卡片到「预约中」列
     - 生成患者准备须知（多语言，基于知识库）
     - 推送通知到患者 APP：「Your appointment is confirmed...」
     - 设置检查前一日提醒
     - 在患者 Timeline 上添加节点

5. **患者 APP 同步更新**
   - 患者打开 APP，Today 页显示：
     - "Fetal echocardiography at B Hospital"
     - 日期时间、地址、导航按钮
     - "Bring: referral letter, passport, insurance card"
     - "Check-in on 3rd floor, Ultrasound Department"

**价值点：** 即使在没有 API 的现实约束下，系统也把「打电话预约」这件原本零散的活，变成了结构化、有记录、可自动触发后续动作的标准流程。

**关键界面：**
- 引导式预约界面（Step 1-3）
- 预约结果确认页（Step 4）
- 患者 APP Today 页（Step 5）

### Flow 4：知识沉淀 — 创建任务链模板

**场景：** 顾问处理了一个系统里没有模板的转诊类型（如「基因检测 @ C医院」），处理完后把这次经验保存为模板，供团队复用。

**入口：** 任务链编辑页 → 「保存为模板」 或 模板库 → 「+ 新建模板」

**步骤：**

1. **触发保存模板**
   - 顾问完成一次新的转诊流程后，在患者详情页点击「保存为模板」
   - 或直接在模板库点击「+ 新建模板」

2. **填写模板元信息**
   - 模板名称：基因检测 @ C医院
   - 适用场景：私立医院转诊至 C医院 做产前基因检测
   - 标签：#C医院 #基因检测 #产前 #需要空腹
   - 预计时长：7 个工作日
   - 难度等级：中等

3. **搭建任务链**
   - 从空白画布开始，或从已有模板复制修改
   - 拖拽添加任务节点：
     1. 确认检测项目
     2. 查询C医院检测要求
     3. 预约采血时间
     4. 发送空腹/停药须知
     5. 当日导航与签到
     6. 跟踪报告周期（通常 10-14 天）
     7. 解读报告并转发医生
     8. 安排遗传咨询
   - 为每个节点设置：执行者、依赖、文档、通知规则、异常处理

4. **关联知识库条目**
   - 每个任务节点可链接到知识库条目
   - 例如「预约采血时间」链接到「C医院检验科预约方式」
   - 「发送空腹须知」链接到「基因检测前准备事项（EN/CN）」

5. **设置模板可见范围**
   - 选择：仅自己 / 团队共享 / 需要管理员审核
   - 添加版本说明："v1.0 基于 2024年8月 Sarah Hill 案例创建"

6. **发布与复用**
   - 发布到模板库
   - 其他顾问在创建新患者时可以看到此模板
   - 未来有同类转诊时，一键调用，自动填充标准流程

**价值点：** 把个人经验变成团队资产，让新人顾问也能快速处理复杂转诊，实现服务标准化和规模化。

**关键界面：**
- 模板创建入口（Step 1）
- 模板元信息填写（Step 2）
- 任务链拖拽编辑器（Step 3-4）
- 模板库卡片展示（Step 6）

### Flow 5：患者引导旅程（C端）

**场景：** 患者 Sarah 收到顾问为她安排的转诊计划，按照 APP 指引完成整个就医过程。

**入口：** 患者收到短信/邮件/APP 推送 → 打开 BridgeCare Patient APP

**步骤：**

1. **首次打开 APP**
   - 简洁欢迎页："Your care team is here to guide you."
   - 使用医院提供的验证码或护照号登录
   - 选择母语（默认 English，可切换）

2. **查看 Today 首页**
   - 大卡片显示："Your coordinator is confirming your appointment at B Hospital."
   - 下方小字："We will notify you once it's scheduled."
   - 底部固定按钮：「Contact Coordinator」

3. **预约确认后**
   - Today 首页更新："Fetal echocardiography on Aug 23, 2:00 PM"
   - 卡片包含：医院名称、地址、导航按钮、需要携带的文件清单
   - 倒计时："In 2 days"

4. **检查前一天**
   - 收到系统推送："Reminder: Your appointment is tomorrow."
   - 打开 APP 查看准备事项：空腹要求、停车建议、建议到达时间

5. **检查当天**
   - Today 显示："Go to B Hospital, 3rd Floor, Ultrasound Department"
   - 点击导航按钮跳转地图
   - 到达后点击「I have arrived」签到
   - 顾问端 Kanban 自动显示「已签到」

6. **报告出具后**
   - APP Timeline 更新："Report is ready"
   - 患者可查看报告摘要（非医学解读，仅说明"已出"）
   - 下一步提示："Your coordinator will arrange a follow-up with your doctor."

7. **复诊安排**
   - Today 显示："Follow-up at A Hospital on Aug 26, 10:00 AM"
   - 患者可一键确认或申请改期

**价值点：** 患者在整个过程中始终知道"下一步该做什么"，焦虑被转化为确定性。

**关键界面：**
- APP 登录/欢迎页（Step 1）
- Today 首页（Step 2-3-5）
- Timeline 全旅程页（Step 6-7）
- Help/Contact 页面（贯穿）
