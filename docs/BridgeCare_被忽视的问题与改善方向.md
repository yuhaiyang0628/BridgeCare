# BridgeCare — 被忽视的两个问题与改善方向

> 反思定位：项目已完成"功能完备 + 叙事完整"的阶段，但缺两样东西——
> 1）平台缺一个**统摄性的设计概念**（让人一看就记住"为什么是 BridgeCare"）；
> 2）叙事缺**故事感与"我"的逆风盘**（一路顺风的汇报，看不到你打硬仗的能力）。
> 本文给出诊断 + 改善方向，两者其实是同一件事的两面。

---

## 一、平台设计：缺一个"概念"，而不缺功能

### 现状诊断
当前 BridgeCare 在功能上是一个完备的 case-management / 协作工具：建病人、Kanban 追踪、任务链模板、引导式预约、患者 App。但拆开看，它的组件（Kanban、模板、Modal、移动端 Today）在市面上都能找到对应物——它像一个"穿了医疗皮肤的项目管理工具"。

评审者看完会想：**这跟 Asana + 一个医疗插件有什么区别？**

缺的不是功能，是一个**设计立意（design thesis）**——一句话能说清"为什么 BridgeCare 必须是 BridgeCare，而不是通用工具"。

### 核心张力：建议显式立起"不可能三角"
我们在架构阶段其实已经埋下了张力，但没把它**立起来作为概念**。我建议把 BridgeCare 的核心张力明确包装成不可能三角：

> **自动化效率  ⇄  个性化适配  ⇄  高风险零容错**

- 第一版（直觉方向）会想猛推"自动化"：医院 API 对接、智能路由、自动预约，听起来性感。
- 但调研显示：中国医院 IT 碎片化 + 国际患者 high-stakes + 跨语言，全自动要么不可行、要么危险（一步漏掉 = 患者 stranded）。
- **我们做的 tradeoff**：把"自动化"压下来，把"个性化"（可定制任务链）和"安全"（人在环内 + 异常预警）顶上去。

这个三角就是产品的"概念锚点"——它解释了每一个设计决策为什么长这样。

### 三个候选概念（推荐第 1 个）
1. **「人在环内的连续性编排层」（Human-in-the-loop Orchestration for Continuity）** — 推荐。把"协调员 = 系统的人肉补丁"洞察转化为产品哲学：BridgeCare 不替代人，而是把人的隐性知识外化、把断裂的连续性重新缝合。最差异化、最贴合调研。
2. **「连续性作为一等公民」** — 以"患者跨院旅程"为持久对象，医院只是节点。偏架构视角，稍学术。
3. **「翻译层」** — 在系统间 / 语言间 / 医患认知间做翻译。诗意，但弱化了"编排 / 协调"这个核心动作。

### 让概念"长"在界面上（不止是文案）
概念必须有一个**签名交互（signature moment）**让人一眼记住。候选：
- **引导式预约的通话编排屏**：协调员在打电话，系统在右侧喂话术、实时捕获结果。这就是"人在环内"的具象化——不是自动拨号，是人拿着系统给的剧本在演。**建议立为产品 hero interaction。**
- **任务链可视化**：把 10 步依赖链画成"乐谱"，协调员是指挥。比 Kanban 列更能传达"编排"概念。

> 改善动作：在 Page 4 (Key Design) 用一整块讲"为什么我们不做全自动"，把引导式预约屏作为概念证明，而不是又一个功能截图。

## 二、叙事结构：缺故事感与"我"的逆风盘

### 现状诊断
现有叙事是"我们做了研究 → 得出洞察 → 做了方案"的线性汇报。专业但**平**。缺两样：
1. **"我"的位置**：决策看起来是客观推导出的，没有展现你作为设计师 / PM 在模糊处的判断与担当。
2. **不完美的点**：没有失败、没有卡顿、没有 tradeoff 的挣扎。评审者看不到你"打逆风盘"的能力。

你的婴儿体温贴项目之所以好，是因为有那个"不可能三角"的**失败 → 分析 → tradeoff → v2 过关**的弧线。BridgeCare 目前是"一路顺风"的呈现。

### 建议插入的 2–3 个"逆风盘"节拍
统一结构：**尝试 → 撞墙 → 理性 tradeoff → 结果**

**节拍 1：自动化的诱惑（最该讲）**
- 尝试：最初方向想做"跨院自动预约"——对接医院系统、智能排程，听起来性感。
- 撞墙：调研发现目标医院几乎不开放 API；且国际患者一次漏约后果严重，全自动不可接受。
- Tradeoff：你作为设计负责人，主动砍掉"全自动"这个更性感的方向，选择"引导式人工 + 系统在环"——效率让位于安全与可行。
- 结果：引导式预约模块诞生，反而成为产品最独特的记忆点。

**节拍 2：模板的陷阱**
- 尝试：用任务链模板把协调员知识标准化、规模化。
- 撞墙：试点里 Emma（罕见病）完全套不进标准模板，强套导致关键步骤被忽略。
- Tradeoff：不在"标准化"和"灵活"间二选一，而是在模板后强制加"定制"层——模板是起点不是终点。
- 结果：向导第 4 步 Customize 成为安全网。

**节拍 3：主动砍薄患者端**
- 尝试：想给 C 端做丰富体验。
- 撞墙：协调员认知负荷已饱和，胖患者端只会带来更多 incoming 疑问。
- Tradeoff：显式把患者 App scope 砍到极简（Today / Timeline / Help），保护 B 端注意力。
- 结果：双端分工清晰，体现成熟优先级判断。

### "我"如何入镜
在 Research → Solution 之间插一个**第一人称 interstitial（设计师的两难）**：
> "看到数据那刻，我的第一反应是做全自动。但 Emma 的病例和三家医院 IT 现状让我改了主意。下面是我做的几个关键 tradeoff——以及为什么我愿意为'安全'放弃'性感'。"

再配一个 **Decision Log** 区块：3–4 个决策按「情境 → 我的初始倾向 → 被什么约束打脸 → 我做的 tradeoff → 结果」呈现。

### 在 5 页结构里的落点
- **Page 2→3 之间**：加半页 / 一屏 "Hard Turns / 逆风盘"，放在 Synthesis 之后、Solution 之前。让概念（人在环内）是"被打出来的"，不是凭空宣布的。
- **Page 4**：把"为什么不做全自动"作为 Key Design 第一条设计原则，配引导式预约屏为证据。
- **Research 页**可保留一小块"失败的原型方向"展板（类似体温贴的 v1 失败示意）。

## 三、两个问题的合流（关键洞察）
被忽视的两件事其实是**同一件事的两面**：
- 平台缺的"概念" = **人在环内的连续性编排**
- 叙事缺的"故事" = **这个概念是怎么被现实打出来、被你用 tradeoff 守住的**

把"逆风盘"讲清楚，概念就自然立住了；概念立住了，平台就不再是"医疗版 Asana"，而是一个有立场、有记忆点的设计。两者互相成就。

---

## 四、立即可做的 3 件事
1. 在原型 / 排版里把**引导式预约通话屏**立为 hero interaction，旁注"我们刻意不做全自动"。
2. 在 Page 3 后插入 **"Hard Turns"** 半页，放 2–3 个逆风盘节拍 + 第一人称引言。
3. 给产品一句**设计立意 tagline**，例如：
   *"BridgeCare — 把协调员的人肉补丁，变成系统在环的连续性。"*

---

## 五、一句话给你的学生讲清楚
"我们前几轮把功能和叙事都做全了，但还差最后一步：给平台一个**能记住的概念**，给故事一段**能佩服的逆风盘**。这两件事合起来，就是让作品从'做得好'变成'让人忘不掉'。"
