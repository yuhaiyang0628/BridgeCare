# BridgeCare v6 · Arco 风格工作台方向稿

v6 是从 v5 复制出的独立目录。原始高保真原型、v2、v3、v4、v5 均未修改。当前先呈现 Dashboard、病例页、引导式预约页及共享工作台外壳的视觉方向；其他流程页尚未进行完整视觉重构，等待方向确认后再铺开。

## 打开原型

直接打开本目录的 `index.html`。页面默认使用英文，并载入 Sarah Johnson 的 **Booking overdue** 演示病例。界面使用本地系统字体回退，不依赖在线字体服务。

## 设计 tokens

- 主交互色：`#165DFF`；悬停色：`#0E42D2`；选中浅底：`#E8F3FF`。
- 页面底色：`#F5F7FA`；表面：`#FFFFFF`；次级表面：`#F7F8FA`。
- 正文：`#1D2129`；次级文字：`#4E5969`；辅助文字：`#86909C`。
- 边框：`#E5E6EB`；焦点环：`rgba(22, 93, 255, .24)`。
- 成功：`#00B42A` / `#E8FFEA`；等待：`#FF7D00` / `#FFF7E8`；需处理：`#F53F3F` / `#FFECE8`。
- 字体优先使用 Inter，并回退至系统字体、PingFang SC、Hiragino Sans GB、Microsoft YaHei。正文 14px；中文模式沿用同一可读字号。
- 4px 间距基准，常用 4、8、12、16、20、24、32px。控件圆角 4–6px，卡片 8px，浮层 10px。
- 卡片依靠边框和留白分层；阴影只用于轻量浮层。异常、等待和成功均保留文字与图标，不单靠颜色区分。
- BridgeCare 的识别点是病例页与预约页贯穿的交接线和节点，表示转诊、预约、就诊、报告与随访连续交接。

颜色、布局、圆角和字体选取参考 [Arco Design 主题变量](https://arco.design/themes/design/11843)、[Arco Design 组件变量示例](https://arco.design/themes/design/2522)。项目仍使用原生 HTML/CSS/JavaScript，没有迁移到 Arco React。

## 保留的产品行为

- 中英文切换分别保留顾问工作台语言与患者预览语言；重置病例不重置语言。
- `Demo scenarios` 包括 **Start from referral**、**Booking overdue** 和 **Report delayed**。演示预设仍通过状态模型构造，不能由页面直接拼出不一致的病例字段。
- Booking overdue → 异常复核 → Guided booking 保留；未接通记录为重试，不会标记预约成功。接通确认后顾问端与患者预览共享同一预约信息。
- 报告收到、医生审阅和随访安排仍是分开的状态；报告收到后必须完成医生审阅，才能继续随访安排。
- Activity 仍按事件和参数，在顾问端当前语言下渲染；患者预览继续按病例首选语言显示，并可用独立控件预览另一种语言。
- `Reset demo` 回到默认 Sarah 预约超时病例；从空白开始请使用 **Start from referral**。

## 演示路径

1. Dashboard 的 Sarah 病例卡提供 **Sarah’s case**、**Review alert** 和 **Patient preview** 直达入口；Demo scenarios 保留在病例卡下方，异常提醒另有详情卡。
2. 打开 **Sarah’s case** 查看任务链及 BridgeCare 交接线，再进入 **Review alert** 查看医院预约上下文。
3. 打开 **Guided booking**。选择 **No answer**，记录原因与重试期限；返回病例确认状态仍为待重试，再次进入预约并选择 **Connected**，填写并确认医院提供的预约信息。
4. 患者预览确认预约时间、医院、地点和说明与顾问记录一致。可单独切换患者预览语言。
5. Dashboard → **Demo scenarios** → **Report delayed**，进入报告工作流；依次记录报告收到、医生已审阅、安排随访。
6. **Start from referral** 会清空当前病例并打开五步向导。完成录入、任务链选择与启动后，病例以向导输入的数据建立。
